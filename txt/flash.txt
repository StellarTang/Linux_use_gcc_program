C语言全局变量初始化函数优化Flash空间完整指南
=============================================
生成日期：2026年10月4日
适用场景：嵌入式单片机低资源Flash优化

一、核心优化逻辑
---------------------------------------------
将原本直接带非零初值定义的全局变量，改为先声明为未初始化状态，
再通过专门的初始化函数批量赋值，利用内存段特性节省Flash空间：
1. 未初始化全局变量进入.bss段，完全不占用Flash空间，仅占用RAM
2. 直接带非零初值的全局变量进入.data段，必须在Flash中存储完整初始值副本

二、空间占用详细对比
---------------------------------------------
1. 直接初始化全局变量（传统写法）
   - 32位int类型变量：固定占用4字节Flash纯数据空间
   - 100个变量场景：直接占用400字节Flash，随变量数量线性增长
   - 额外开销：启动代码需要执行循环拷贝，将Flash数据搬运到RAM

2. 函数内赋值初始化（优化写法）
   - 小整数（0-255）：ARM Cortex-M架构下，赋值指令仅占2~4字节
   - 100个变量场景：优化后仅占用100~200字节Flash，远低于直接初始化
   - 无额外拷贝开销：CPU直接执行指令将数值写入RAM，省去启动搬运逻辑

三、适用边界与盈亏平衡点
---------------------------------------------
| 变量数量 | 推荐方案 | 原因说明 |
|----------|----------|----------|
| <5个     | 直接初始化 | 函数的固定调用开销反而超过节省的空间 |
| 5~10个   | 二选一均可 | 两种写法Flash占用基本持平 |
| >10个    | 初始化函数 | 指令密度远高于纯数据存储，大幅节省Flash |

* 特殊例外：大整数、浮点数不适用该优化，直接初始化4字节固定占用更省空间

四、完整可运行代码示例
---------------------------------------------
// global_vars.h 全局变量声明
#ifndef GLOBAL_VARS_H
#define GLOBAL_VARS_H

extern int config_param1;
extern int config_param2;
extern float sensor_cali;
extern char dev_name[32];

#endif

// global_vars.c 变量定义（全部未初始化，不占Flash）
#include "global_vars.h"

int config_param1;
int config_param2;
float sensor_cali;
char dev_name[32];

// system_init.c 专门的变量初始化函数
#include "global_vars.h"
#include <string.h>

void System_GlobalVars_Init(void)
{
    config_param1 = 100;
    config_param2 = 200;
    sensor_cali = 1.5f;
    strcpy(dev_name, "STM32_Sensor_Dev");
}

// main.c 启动流程调用
#include "global_vars.h"

int main(void)
{
    Hardware_Base_Init();
    // 必须在所有业务逻辑前调用变量初始化函数
    System_GlobalVars_Init();
    
    while(1)
    {
        // 业务逻辑代码
    }
}

五、关键注意事项
---------------------------------------------
1. 必须保证初始化函数在访问这些全局变量之前被调用，否则变量默认值为0
2. 开启编译器-Os优化等级，编译器会自动压缩赋值指令体积，进一步放大优化收益
3. const常量、大型查找表不适用该优化，这类数据直接存放在Flash的.rodata段，本身就不占用RAM
4. 字符串常量会自动存放在Flash的.rodata段，仅在大量字符串场景下优化收益会被部分抵消
